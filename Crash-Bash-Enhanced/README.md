# Crash Bash Enhanced — PS3 / Online foundation

This branch contains the native PS3 homebrew shell and the first cloud-lobby integration.

## Current scope

- Native PSL1GHT / Tiny3D PS3 application.
- XMB-installable PKG build workflow.
- Local guest identity; no PSN initialization or PSN login.
- Controller navigation and an offline input-test arena.
- Web lobby for two-player public/private rooms.
- Guest tokens signed by a server-only HMAC secret.
- Private Vercel Blob storage for temporary room presence and signaling records.
- Native PS3 HTTPS client using libcurl + PolarSSL: health check, public room list, create/join, ready heartbeat, room refresh and leave.
- PS3 room controls: browse public rooms, create public/private rooms, and join a six-character invite code from the controller.
- Host protocol and JSON parser tests, PS1 DAT sector-reader tests, deterministic input-packet codec tests, BIN/CUE and PS-X EXE extraction tests, plus web lobby security tests.

## Honest implementation status

This is **not yet the complete Crash Bash game**. The repository does not contain the original game engine, original mini-games, levels, or copyrighted game assets.

The Vercel lobby API is deployed. Its health endpoint confirms that private storage and guest-token signing are configured, and the public-room endpoint responds. The PS3 menu now has code to connect to that API over HTTPS and perform the lobby actions above.

On the PS3 room screen, L1 switches the next room between public and private; R1 opens invite-code entry (D-pad left/right selects a character, up/down changes it, Cross joins). The current lobby is limited to two players. Real-time gameplay transport is not implemented: the service does not yet carry per-frame game inputs. NAT traversal, relay fallback, and integration with the original Crash Bash engine remain outstanding. A successful room connection must not be described as a playable online match.

## Hosting and cost

This stage uses the existing Vercel project and its existing private Blob store. No new Supabase project or separate paid hosting service was created during this stage. The account plan and current usage quotas have not been independently verified; check them before public release. The project must not silently upgrade or create paid resources.

## PSN independence

The PS3 client does not initialize NP / PSN services. Player identities are generated by this project and are independent of Sony accounts. This does not remove or bypass a console/network ban from Sony services; it simply avoids using PSN.

## Build

GitHub Actions uses ghcr.io/02900/ps3-toolchain-tiny3d:latest, which includes PSL1GHT, Tiny3D, libcurl and PolarSSL. The build:

1. Downloads the Mozilla CA bundle from curl.se into pkgfiles/USRDIR/cacert.pem.
2. Compiles the native PS3 application.
3. Builds the SELF and PKG outputs.
4. Checks the PKG header and uploads build artifacts.

TLS peer and host verification remain enabled; the client does not disable certificate validation.

Expected artifacts:
- crashbash.elf
- crashbash.self
- crashbash.pkg
- crashbash.gnpdrm.pkg

A successful CI build is not a substitute for testing on RPCS3 and a physical PS3.

## Web lobby

The Vercel project deploys from the repository root. The root index.html and api/ files mirror the web app/API source for deployment.

Required server-side environment:
- CB_TOKEN_SECRET: random secret used to sign guest tokens.
- BLOB_READ_WRITE_TOKEN: injected by the connected private Vercel Blob store.

Endpoints:
- GET /api/health
- GET /api/rooms
- GET /api/rooms?code=ABC234 (requires a guest bearer token)
- POST /api/rooms with actions create, join, heartbeat, poll, signal, and leave.

Room storage is temporary and designed for matchmaking/presence only, not per-frame gameplay traffic.

## Engine-port groundwork

A disc extraction tool now reads a retail PS1 BIN/CUE (Mode 2/2352), locates `CRASHBSH/CRASHBSH.DAT` and `SCUS_945.70` in ISO9660, reads the 992-entry DAT index from the PS-X EXE at virtual address `0x8004E110`, splits the archive into indexed files plus filler, and verifies a byte-identical reconstruction. It writes user-owned game data only to the chosen local output folder; no copyrighted game data is committed. The native PS3 archive reader remains an isolated file-I/O primitive, and the original engine, renderer, audio and gameplay are not yet integrated into the PS3 executable.

Run `make host-test` to execute the archive, protocol, JSON, netcode and disc-extractor tests. To extract a retail BIN/CUE locally, run `python3 tools/extract_disc.py --bin "Crash Bash (USA).bin" --cue "Crash Bash (USA).cue" --out ./assets` from this directory.

## Online gameplay transport groundwork

A fixed 24-byte input-packet format is now defined and tested. It carries a protocol version, monotonically assigned sequence number, game-frame number, controller button mask, acknowledgement field and CRC-32 integrity check. The decoder rejects malformed lengths, unsupported versions and corrupted packets before exposing input data. This is the wire-format foundation only: it is not yet connected to a UDP peer transport, a game simulation loop, rollback/prediction, or the original Crash Bash modes. The existing HTTPS room service remains matchmaking/signaling, not a per-frame gameplay relay.
