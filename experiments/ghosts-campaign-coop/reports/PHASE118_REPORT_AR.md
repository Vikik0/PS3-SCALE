# تقرير المرحلة 118 — حصر استدعاءات التفاعل الأصلية

## نتيجة التدقيق

راجعت ملفات GSC الأصلية من أرشيف المهمات المقدم، وتأكدت من وجود 15 استدعاءً للدالة القديمة waittill_trigger:

- Black Ice: 3.
- Carrier: 2.
- Cornered: 10.

كل الاستدعاءات ما زالت تستخدم الدالة القديمة ولا تمرر كيان لاعب صريحاً إلى النسخة الجديدة. أضفت جدولاً تفصيلياً بالملف والسطر واسم الدالة المستدعية في ملف inventory.

## أهم أربع سلاسل تفاعل

1. Black Ice — event_player_turns_key، Event ID 0.
2. Carrier — cut_the_rope، Event ID 1. هذا المسار يستخدم notifyonplayercommand("cut")؛ لذلك أصبح Adapter أوامر اللاعب في Phase 117 مناسباً له من ناحية نوع الحدث، لكن لم يتم ترحيل الدالة نفسها.
3. Cornered — gun_down_trigger_internal، Event ID 2.
4. Cornered — upload_virus_enter، Event ID 3.

كل سلسلة تحتاج تمرير اللاعب الفعلي من لحظة التفاعل حتى نهاية الـHandler، مع إبقاء الـflags والـanimations والـdvars المشتركة تحت منسق واحد.

## قرار التنفيذ

لم أقم بتعديل استدعاءات المهمات بشكل جماعي؛ ذلك سيبقي level.player داخل معظم السلاسل وقد يعطي انطباعاً زائفاً بأن Player 2 مدعوم. الخطوة التالية هي ترحيل تفاعل واحد فقط بعد إثبات Native Campaign Player 2 على الجهاز الفعلي، ثم اختبار ملكية الحدث والإنهاء والإلغاء.

لا يوجد تعديل على EBOOT أو SELF أو FastFile. Player 2 ما زال NOT_PROVEN والتفاعلات المشتركة 0/4.
