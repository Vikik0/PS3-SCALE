# تقرير المرحلة 49 — تدقيق ربط OPD بالدوال

## المشكلة

المرحلة 48 كانت تربط OPD descriptor بالدالة التي تحتوي عنوان الكود. لكنها لم تفرق بين عنوان يساوي بداية الدالة وعنوان يقع داخل جسمها، كما كانت تتجاهل عناوين كود تنفيذية لم يستطع Ghidra ربطها بأي دالة.

## التعديلات

1. أصبح التحليل يصنف كل code pointer تنفيذي إلى تطابق مباشر مع بداية الدالة أو تطابق مع دالة تحتوي العنوان أو عنوان غير مربوط.
2. أضيف إلى CSV عدد descriptors المطابقة لبداية الدالة وعدد المطابقة داخل جسم الدالة.
3. أضيف تقرير JSON يحصي جميع خانات OPD: الفارغة وغير الفارغة وغير المقروءة، والمؤشرات غير الصالحة، والتطابقات المباشرة والداخلية والمؤشرات غير المحلولة.
4. أصبح runner يقارن تقرير التحليل مع تقرير OPD seeder ومع أعداد CSV لكل دالة. أي اختلاف يوقف العملية قبل استبدال أي مخرجات.
5. يعرض تقرير المقارنة قوة دليل OPD لكل مرشح، ويفصل بين التطابق المباشر والتطابق داخل الدالة.
6. بقي دعم ملفات المرحلة 48 القديمة، لكن تظهر حالتها NOT_RECORDED بدلاً من افتراض نوع التطابق.

## التحقق

الاختبارات تستخدم بيانات صناعية وتشغيل Ghidra وهمياً لاختبار توازن الأعداد ومنع ترقية ملفات جزئية عند وجود اختلاف.

هذا لا يثبت أن أي دالة يمكن استدعاؤها بأمان داخل Campaign، ولا يثبت إنشاء Player 2. نحتاج ملفات PPU المطابقة وتشغيل Ghidra الفعلي لإنتاج دليل حقيقي.
