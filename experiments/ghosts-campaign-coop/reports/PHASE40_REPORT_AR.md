# تقرير المرحلة 40 — تمييز الاستدعاء المباشر عن المحسوب

## الهدف

بعد فصل مراجع CALL عن DATA في المرحلة 38، أضفت تمييزاً إضافياً داخل مراجع CALL نفسها. Ghidra يستطيع تحديد ما إذا كان المرجع مباشراً أو محسوباً، والمرجع المحسوب قد يمثل استدعاءً غير مباشر، لذلك لا يجب إعطاؤه نفس أولوية الاستدعاء المباشر.

## التعديلات

1. أضاف سكربت Ghidra الحقل is_computed باستخدام RefType.isComputed().
2. أصبح المحلل يميز بين direct_call وcomputed_call وdata وcomputed_non_call وباقي المراجع.
3. مرشحو Multiplayer الذين لديهم direct call يظهرون قبل مرشحي computed call، ثم تأتي فروقات بصمات الدوال.
4. أضيفت أعداد الاستدعاءات المباشرة والمحسوبة إلى Manifest وملخص التقاط PS3.
5. تم تحديث مخطط JSON للمقارنة إلى الإصدار 3.
6. أضفت اختباراً يثبت ترتيب الأولوية بين الاستدعاءات المباشرة والمحسوبة.

## نتيجة CI

نجح GitHub Actions run رقم 45262667084 في الوظائف الخمس و313 اختبار Python، بما فيها تصنيف الاستدعاءات المباشرة والمحسوبة.

## حدود المرحلة

هذه الأولوية تحليلية فقط. لا يمكن معرفة عدد الاستدعاءات الفعلية أو المرشحين الحقيقيين قبل تشغيل Ghidra على ملفي PPU الأصليين المطابقين. لم يتم اعتماد أي Hook أو إثبات Player 2.
