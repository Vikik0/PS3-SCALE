# تقرير المرحلة 42 — فحص محاذاة جدول OPD ومؤشرات التعليمات

## التعديلات

1. أضفت شرط أن يكون عنوان بداية جدول OPD محاذياً على 8 بايت.
2. أضاف سكربت Ghidra فحصاً بأن عنوان كود كل descriptor محاذٍ على 4 بايت قبل disassemble أو createFunction.
3. أضيف التحقق في Python runner وفي Java seeder حتى لا يعتمد الأمان على طبقة واحدة.
4. بقيت فحوص حجم الجدول ونطاق 32-bit وعدم تجاوز الذاكرة والمحاذاة السابقة فعالة.

## الاختبارات

أضيف اختبار جديد لحالات OPD base غير المحاذية في واجهة CLI وواجهة Python المباشرة، كما تم توسيع فحص مصدر Java للتحقق من شرط محاذاة الكود.

## الحدود

المحاذاة شرط صحة أساسي لكنها لا تثبت أن كل descriptor يمثل دالة صحيحة. يلزم استخدام نطاق OPD المستخرج من ELF inspector والتحقق من وجود الكود داخل ذاكرة تنفيذية في Ghidra.
