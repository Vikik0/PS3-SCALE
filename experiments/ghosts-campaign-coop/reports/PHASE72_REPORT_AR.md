# تقرير المرحلة 72 — تقوية بوابة جاهزية اللاعب الثاني

## المشكلة التي عالجتها المرحلة

كانت بوابة `ghc_local_player_gate_validate()` تتحقق من وجود لاعبين Native ومن اختلاف بعض عناوين `gclient` و`gentity` و`playerState`، لكنها لم تشترط أدلة مستقلة على:

- وجود إطار إدخال صالح وحديث لكل لاعب.
- أن ملاحظتي اللاعبَين جُمعتا ضمن إطار المحرك نفسه.
- وجود Command Buffer مستقل لكل لاعب.
- وجود سياق View/RefDef/Camera مستقل.
- وجود سياق HUD مستقل.

وبالتالي كان من الممكن أن تمر ملاحظات فيها لاعبان مختلفان شكلياً لكنهما يشتركان في مسار إدخال أو عرض واحد.

## التعديلات

1. أضفت `input_frame_valid` و`observation_frame` إلى ملاحظة كل لاعب.
2. أضفت عناوين `input_command_address` و`view_context_address` و`hud_context_address`.
3. أصبحت البوابة ترفض إطار الإدخال المفقود أو غير الصالح.
4. أصبحت ترفض اختلاف رقم إطار الرصد بين اللاعبَين.
5. أصبحت تشترط عناوين مستقلة لأوامر الإدخال والكاميرا/HUD، وتفحص التداخل بين كل فئات العناوين عبر اللاعبَين.
6. أضفت حالات فشل منفصلة للبيانات الجديدة، مع الإبقاء على أرقام الحالات القديمة دون تغيير.
7. وسعت اختبارات C لتشمل المدخلات القديمة والجديدة، واختباراً يؤكد أن `local_client_num` لا يُفترض أنه يساوي رقم منفذ يد التحكم.
8. حدّثت محاكي الاختبارات المضادّة ليكشف مشاركة Command Buffer أو Camera أو HUD، وغياب إطار إدخال حديث، واختلاف إطار الرصد.
9. أصلحت مسار الوسيط الفارغ: إذا كانت مصفوفة اللاعبين `NULL` مع وجود نتيجة، تعيد البوابة تهيئة النتيجة إلى فشل واضح بدلاً من ترك حالة `READY` قديمة.

## التحقق المحلي

- اختبار بوابة اللاعب C: ناجح مع `-std=c11 -O2 -Wall -Wextra -Werror -pedantic -fsanitize=address,undefined`.
- فحص صياغة محاكي التشغيل C نجح مع `-Wall -Wextra -Werror -pedantic`.
- اختبارات الحالات الجديدة تشمل فقدان input frame، اختلاف observation frame، تكرار command buffer، تكرار view context، تكرار HUD context، ورفض نتيجة قديمة عند تمرير مؤشر لاعبين فارغ.

## حدود المرحلة

هذه تقوية لبوابة التحقق وليست إنشاءً للاعب الثاني. لا يوجد حتى الآن Adapter يجمع هذه العناوين من محرك Ghosts، ولا Hook مثبت في Campaign، ولا اختبار PS3/RPCS3 يثبت أن اللعبة توفر فعلياً هذه السياقات المستقلة.

تبقى بوابة native runtime كما هي: يجب تحليل ملفات TU 1.16 المطابقة وبيانات PS3MAPI الفعلية قبل السماح بأي ربط أو تعديل في Campaign. لا يتم إعلان نسخة تعاونية قابلة للعب بناءً على اختبارات المضيف وحدها.
