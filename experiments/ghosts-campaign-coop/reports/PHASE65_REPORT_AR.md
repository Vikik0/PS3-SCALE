# تقرير المرحلة 65 — تحليل موحد ومثبت البصمة لمسارات Player Container

## الهدف

المرحلة 64 ربطت قائمة الدوال الدقيقة مع Call Graph، لكن كان لا يزال هناك تسليم يدوي بين تقرير Ownership وتقرير Call Graph. هذه المرحلة تجعل العملية أمراً واحداً وتضمن أن الملفّات لم تتغير أثناء التحليل.

## التعديلات

1. أضفت runner موحداً يشغّل Ownership Audit ثم يستخرج منه جميع دوال player-container بالمسار واسم الدالة بدقة.
2. يشغّل بعدها GSC Call Graph على نفس مجلدات المصدر، مع منع خلط الدوال المتشابهة الاسم في ملفات مختلفة.
3. يحسب SHA-256 لكل ملف GSC ويبني بصمة مجلد مستقرة قبل التحليل وبعده.
4. إذا أضيف أو حُذف أو تغير أي ملف أثناء التحليل، يرفض التقرير ولا يكتب نتيجة مجمعة.
5. يمنع إدخال ملفات GSC عبر Symbolic Links خارج مجلد المهمة.
6. يكتب JSON بشكل Atomic ويرفض الكتابة فوق تقرير موجود إلا عند تحديد overwrite صراحةً.

## الاختبارات

أضيفت ستة اختبارات للتشغيل المتكامل، والدوال المتكررة الأسماء، وتغيير الملفات أثناء التحليل، وبصمة ملفات المصدر، وحماية التقرير الموجود.

## الحدود

النتيجة تحليل ساكن لملفات GSC فقط. لا تثبت تنفيذ callbacks فعلياً أو إنشاء Player 2 Native داخل Campaign.
