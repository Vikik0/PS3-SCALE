# تقرير المرحلة 50 — تحليل منطقة الذاكرة الخاصة بـTOC

## الهدف

مجرد وجود عنوان TOC داخل ذاكرة Ghidra لا يكفي لمعرفة طبيعة المنطقة التي يشير إليها. قد يكون العنوان داخل بيانات للقراءة فقط أو بيانات قابلة للكتابة أو ذاكرة تنفيذية أو منطقة صناعية أضافها التحليل.

## التعديلات

1. أصبح Ghidra يحدد MemoryBlock الذي يحتوي كل عنوان TOC غير صفري.
2. أضيف إلى CSV حقل JSON باسم opd_toc_region_evidence لكل دالة.
3. يسجل الحقل اسم المنطقة وصلاحيات القراءة والكتابة والتنفيذ، إضافة إلى الإزاحة النسبية من بداية المنطقة.
4. لا يسمح لمؤشر صفري أو غير مربوط بادعاء اسم منطقة أو صلاحيات أو إزاحة.
5. أصبح محلل Python يتحقق من شكل JSON ومن تطابق العنوان والحالة والصلاحيات والإزاحة مع عمود TOC الأساسي.
6. أصبحت نتائج مرشحي Multiplayer تعرض معلومات مناطق TOC وعدد المرشحين الذين تشير TOC الخاصة بهم إلى مناطق قابلة للكتابة.

## حدود المرحلة

الاختبارات تستخدم CSV صناعية. صلاحيات MemoryBlock هي بيانات من التحليل الثابت فقط؛ وجود منطقة قابلة للكتابة لا يثبت أن TOC صحيح أو مهيأ أثناء تشغيل اللعبة، ولا يثبت أن الدالة قابلة للاستدعاء بأمان داخل Campaign.
